# 01. 요구사항 Registry (REQ)

> V모델 01. 출처 = 루크 구술 2026-06-15 + 다중 AI 조사·적대리뷰 결론. 상태: `Draft→Approved→In-progress→Done`.
> 모든 REQ는 ≥1 UC·TEST로 닫힌다(orphan 0).

## 기능 요구사항 (FR)

| ID | 영역 | 요구사항 | 상태 |
|---|---|---|---|
| REQ-001 | 투입 | URL 크롤 + 문서 파싱(PDF/HWP/DOCX 등) — 자료 "몽땅" 투입 (NotebookLM류) | Draft |
| REQ-002 | 구조화 | 자료 → 엔티티(서비스·부서·서류·수수료·조건) + 관계 + 서비스카드/FAQ 초안 자동 생성 | Draft |
| REQ-003 | 검증 | **eval-anchored 자가검증** — 운영자가 답한 소수 질의 = 합격 기준(정답 앵커). 생성 KB가 그 답을 재현하는지 자가평가, 통과까지 조정 + 회귀(자료 변경 시 재통과) | Draft |
| REQ-004 | 검증 | 근거 부족·모순·저신뢰 항목만 운영자에게 갭으로 표면화(최소 사람 개입) | Draft |
| REQ-005 | 거버넌스 | 만료/재검토일·승인자·출처·버전·롤백 | Draft |
| REQ-006 | 안전 | 근거 없으면 지어내지 말고 기권+안내. 범위 게이트(법률/자격판단 거부) | Draft |
| REQ-007 | 출력 | grounded 응답(인용 강제) + 서빙 KB export | Draft |
| REQ-008 | 운영자 UX | 비전문가용 폼·승인 워크플로. JSON/임베딩/튜닝 비노출 | Draft |
| REQ-009 | 표현 | 그래프 데이터(엔티티·관계)는 항상 생성. 검색 백엔드(벡터↔그래프)는 RetrievalPort 어댑터 교체 | Draft |
| REQ-010 | 형태 | 서비스(API)로 노출 — 여러 응용이 호출 | Draft |

## 비기능 요구사항 (NFR) — 아키텍처·소유

| ID | 영역 | 요구사항 | 상태 |
|---|---|---|---|
| NFR-001 | 비종속 | 전 구간 port/adapter — LLM·임베딩·검색·저장·파서 어느 것에도 lock-in 금지 (D01) | Draft |
| NFR-002 | 가반성 | 지식 정본 = 표준·문서화 포맷(JSON/관계형) + **무손실 export**. 매니지드 인덱스는 재생성 캐시 (D02) | Draft |
| NFR-003 | 교체가능 | 모든 소비자가 **언제든 본 엔진을 타 솔루션으로 교체 가능** — 설계로 보장 (OWNERSHIP §2) | Draft |
| NFR-004 | 소유 | 넥스테인 소유. 기업·파트너 권리는 별도 계약. 양방향 비종속 (OWNERSHIP) | Draft |
| NFR-005 | 안전 | 출시 전 한국어 질의셋으로 답 품질·기권 보정 측정(과기권/과응답 in-band) | Draft |
